- Implemented behavior:
  - Workload Client CLI (`src/netbalance/workload.py`):
    - Executable via `python -m netbalance.workload`.
    - Mutually exclusive `--count` (count-based request queue) or `--duration` (monotonic time loop with outstanding request drain).
    - Configurable `--host`, `--port`, bounded `--concurrency` (worker coroutine pool, avoiding task bursts), reproducible `--seed` (local RNG for `work_units` 1..3 and payloads), per-attempt `--timeout`, `--output` CSV path, and optional `--trace`.
    - Metadata flags `--policy`, `--scenario`, `--repetition` recorded on each attempt.
    - Single request/response per connection using frozen NDJSON TCP protocol (`encode_message`, `read_message`).
    - Validates response request ID and backend identity; categorizes errors into `CONNECTION_ERROR`, `TIMEOUT`, `MALFORMED_RESPONSE`, `REQUEST_ID_MISMATCH`, or downstream proxy error codes (`OVERLOADED`, `NO_HEALTHY_BACKEND`, `BACKEND_TIMEOUT`, `BACKEND_PROTOCOL_ERROR`, etc.).
    - High-resolution client latency timing via `time.perf_counter()`.
    - Comprehensive CSV recording for all attempts (both successes and failures) with exact columns: `request_id,policy,scenario,repetition,started_offset_s,latency_ms,ok,backend_id,error_code`.
    - Latency statistics (mean, p50, p95, p99 nearest-rank percentiles) computed exclusively over successful attempts; safely reports null/N/A when zero successes occur without crashing.
  - Minimal Dashboard (`web/index.html`, `web/style.css`, `web/app.js`):
    - Vanilla local HTML5 / CSS3 / JavaScript with zero external CDN dependencies.
    - Polls `/api/metrics` every 1.0 second.
    - Renders active policy, in-flight work, metrics epoch, config revision, work accounting totals (`received`, `succeeded`, `failed`, `rejected`, `protocol_errors`), latency stats, backend server table (ID, endpoint, weight, health pill, active work, assignments, successes, failures, probe streaks, last transition timestamp), and recent event stream.
    - Handles disconnected, empty, and API-error states gracefully; clearly distinguishes live API data from test fixtures.
